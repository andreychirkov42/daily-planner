# Clepsy для Android — план

Ветка `mobile`. Решено (26.10.2026): **APK-файл**, данные **хранятся на телефоне** и **синхронизируются с ПК**.

## Устройство приложения

```
Clepsy.apk (~6.5 МБ)
├─ MainActivity (Java, без androidx)  — WebView на http://127.0.0.1:18080/
├─ lib/arm64-v8a/libclepsy.so          — Go-сервер для телефонов (GOOS=android GOARCH=arm64)
└─ lib/x86_64/libclepsy.so             — Go-сервер для эмулятора (GOOS=linux GOARCH=amd64, статический)
```

Готово (шаг 1):
- `android/` — Gradle-проект (AGP 9.4.1, Gradle 9.8.1 через wrapper, compileSdk/targetSdk 37, minSdk 26), пакет `io.github.andreychirkov42.clepsy`.
- `MainActivity` запускает `libclepsy.so` из `nativeLibraryDir` (`-no-tray -no-open -data <filesDir>/data.json -addr 127.0.0.1:18080`), ждёт ответа и открывает WebView. Если сервер уже отвечает (окно пересоздано) — повторно не запускает. Вся логика общая с Windows.
- Переменные окружения для сервера: `TZ` (пояс телефона; база поясов встроена тегом `timetzdata`), `TMPDIR`, `CLEPSY_TOKEN`.
- **Защита API.** К 127.0.0.1 на телефоне может обратиться любое приложение, поэтому при заданном `CLEPSY_TOKEN` `guard` пускает к `/api/` только с cookie `clepsy=<код>`; код хранится в SharedPreferences, cookie ставит оболочка. Страницы без cookie отдаются (в них нет данных). Тест — `TestGuardTokenOnAndroid`.
- `extractNativeLibs` (Gradle: `packaging.jniLibs.useLegacyPackaging = true`) — иначе .so не распакуется и запустить его нельзя.
- android/amd64 без NDK не собирается («requires external linking»), поэтому для эмулятора — обычный Linux-файл. У него нет android-особенностей (DNS читает `/etc/resolv.conf`, которого нет) — для синхронизации по IP это не важно.
- От края до края: отступы под строку состояния, жесты и клавиатуру ставятся из `WindowInsets`. Тема: `values` / `values-night` (по ним WebView отвечает на `prefers-color-scheme`), страница сообщает тему через `ClepsyAndroid.setDark(dark, bg)` — значки строки состояния светлые/тёмные.
- `window.ClepsyAndroid.openUrl(url)` — внешние https-ссылки (кнопка GitHub в настройках); чужие ссылки в WebView тоже уходят во внешний браузер.
- «Назад»: `history.back()` в WebView, на первой странице — свернуть приложение (сервер и Помодоро продолжают работать). Выбор файла для импорта работает (`onShowFileChooser`).
- Значок — тот же, что у exe (`go run ./tools/genicon` пишет и `mipmap-*`), пока обычный, не адаптивный.

Не сделано / потом:
- Экспорт (`/api/export`, скачивание файла) в WebView не работает — нужен `DownloadListener`.
- Уведомления браузера (`Notification`) в WebView недоступны — делать через Android.
- **Подпись:** с v1.2.0-beta.1 — собственный ключ `D:\Android\clepsy-release.jks` (alias `clepsy`), пароли в `android/keystore.properties` (вне git, копия `D:\Android\clepsy-release.properties`). **Ключ нельзя терять:** телефон принимает обновление только с той же подписью, иначе — удаление приложения вместе с данными. Без `keystore.properties` Gradle подписывает отладочным ключом.

## Синхронизация

Модель: у каждого устройства свой `data.json`; при синхронизации телефон отправляет ПК **всё своё состояние**, ПК сливает его со своим и возвращает результат, телефон сохраняет его у себя. Код слияния один (Go) на обеих сторонах.

Что нужно добавить в `store.go`:
- `UpdatedAt` у `Task`, `List`, `Habit`, `Series`, `Sketch` — выставлять при каждом изменении (Create/Update/Toggle/Timer/Reorder/Rollover…).
- Надгробия удалений: `Deleted map[id]time` в `Data` (чистить старше ~60 дней).
- Заметки дня: время правки на дату (`NoteTimes map[date]time`); счётчики Помодоро — слияние по максимуму.
- Правило слияния — «побеждает последняя правка» по сущности целиком (`UpdatedAt`), удаление побеждает правку, сделанную раньше удаления.
- Повторяющиеся задачи: при выполнении копия получает **детерминированный** id (`<id>-<следующая дата>`), чтобы отметка на двух устройствах не дала двух копий.
- Рисунки: метаданные сливаются как остальное, PNG докачиваются отдельными запросами по id.
- Настройки программы (`app`, `pomoSettings`) не синхронизируются — у каждого устройства свои.

Связь:
- На ПК — отдельный слушатель в локальной сети (например `:8092`, только `POST /api/sync` и рисунки), включается в «Настройках» → «Телефон». Там же адрес ПК и код сопряжения; запрос без верного кода — 403. Основной `127.0.0.1:8080` не трогаем.
- При первом включении Windows спросит про брандмауэр — разрешить «Частные сети» должен сам пользователь.
- На телефоне в «Настройках»: адрес ПК + код, кнопка «Синхронизировать», авто-синхронизация при открытии приложения и раз в N минут, если ПК доступен. Работает дома по Wi-Fi; вне дома — тот же механизм через Tailscale (адрес `100.x.x.x`).

## Синхронизация (сделано)

- **Данные:** у задач, списков, привычек и планов есть `updatedAt` (ставится при каждой правке в `store.go`), удаления пишутся в `deleted` (id → время, забываются через 90 дней), правки заметок дня — в `noteTimes`. Повтор задачи получает id `repeatID(id, дата)` — одинаковый на обоих устройствах.
- **Слияние** `mergeData`: побеждает более свежая запись, при равенстве — своя; удаление побеждает правки до него; помидоры — по большему. Холст, настройки Помодоро и программы, `sync` не синхронизируются.
- **ПК:** «Настройки → Телефон» включает приём на `:8092` (флаг `-sync-addr`), показывает адреса и код (8 символов). Отдельный сервер, только `POST /sync` с `Authorization: Bearer <код>`; 10 неверных кодов — пауза 10 минут. Основной интерфейс по-прежнему только на 127.0.0.1.
- **Телефон:** «Настройки → Синхронизация с компьютером»: адрес и код. Обмен делает Go-сервер телефона (`POST /api/sync/run` → ПК), потом сливает ответ со своим. Автоматически — при открытии, при возвращении в приложение и раз в 3 минуты.
- **Первая синхронизация** (`last` пустой) удаляет на телефоне нетронутые списки по умолчанию (иначе «Личное»/«Работа» вернулись бы на ПК). Смена адреса ПК `last` не сбрасывает — иначе удалились бы пустые списки, пришедшие с ПК.
- **Один ПК на телефон:** у ПК свой `sync.id`, телефон запоминает его (`peerId`) и шлёт в `X-Clepsy-Peer`; другой ПК отвечает 409 и ничего не сливает. Так было 26.10.2026: эмулятор, синхронизированный с тестовой копией, подключили к рабочему Clepsy — тестовые правки уехали на ПК. Перейти на другой ПК пока можно только сбросив данные приложения.
- Адрес ПК — только IP: у Go-сервера на телефоне нет системного DNS (`/etc/resolv.conf` на Android нет).
- Коды синхронизации не отдаются в `/api/state` и в файл экспорта (`publicSnapshot`).
- ПК с включённым приёмом раз в минуту перечитывает данные в открытом окне (кроме моментов, когда что-то вводят), чтобы не затереть правку с телефона устаревшей карточкой.
- **Проверка без Windows-брандмауэра:** тестовый ПК `-sync-addr 127.0.0.1:8093`, на эмуляторе адрес `10.0.2.2:8093` (эмулятор видит localhost ПК как 10.0.2.2).
- На настоящем ПК при первом включении Windows спросит, пускать ли Clepsy в сеть — разрешить для частных сетей (решает пользователь).

## Мобильный интерфейс

Сделан в `web/js/mobile.js` + блок «телефон» в конце `style.css`; включается классом `m` на `<html>` (ширина ≤ 760 px, в браузере можно `?mobile`). На компьютере ничего не меняется. Экспорт в приложении скрыт, пока нет `DownloadListener`; уведомления браузера скрыты (в WebView их нет).

## Инструменты (уже установлены через Android Studio)

| Что | Где |
|---|---|
| Android Studio | `D:\Android\Android Studio` |
| JDK (JetBrains Runtime 25) | `D:\Android\Android Studio\jbr` — для Gradle `JAVA_HOME` |
| Android SDK | `D:\Android\Sdk`: platforms `android-37.0`, build-tools `36.0.0`, platform-tools (adb), emulator |
| Эмулятор | образ `android-35/google_apis/x86_64` (Android 15, `sdk_gphone64_x86_64`), в adb — `emulator-5554` |
| Gradle / AGP | в кэше `~\.gradle`: Gradle 9.8.1, Android Gradle Plugin 9.4.1 |

Системные переменные (`JAVA_HOME`, `ANDROID_HOME`, PATH) не заданы и не нужны: пути прописываются в `build-android.ps1` и `android/local.properties` (создаётся скриптом, вне git). `cmdline-tools` (sdkmanager) не установлен — при нехватке компонентов ставить через SDK Manager в Android Studio.

**Ловушка:** Java/Gradle падает с `Unable to establish loopback connection`, если временная папка в пути с кириллицей (`C:\Users\Андрей\AppData\Local\Temp`). Скрипт ставит `TMP`/`TEMP` = `D:\Android\tmp`.

## Сборка

```powershell
.\build-android.ps1            # gofmt, node --check, go vet (+ под android), go test → libclepsy.so ×2 → Clepsy.apk
.\build-android.ps1 -Install   # и поставить на подключённое устройство / эмулятор через adb и запустить
```

Установленный `Clepsy.exe` скрипт не трогает. Эмулятор: `D:\Android\Sdk\emulator\emulator.exe -avd Pixel_8`. На телефон: скопировать `Clepsy.apk` и разрешить установку из этого источника, либо `adb install -r Clepsy.apk` по USB (отладка по USB в настройках разработчика).
