# Clepsy для Android — план

Ветка `mobile`. Решено (26.10.2026): **APK-файл**, данные **хранятся на телефоне** и **синхронизируются с ПК**.

## Устройство приложения

```
Clepsy.apk
├─ MainActivity (Java)         — полноэкранный WebView на http://127.0.0.1:<порт>/
└─ lib/arm64-v8a/libclepsy.so  — тот же Go-сервер, собранный под Android
                                 (GOOS=android GOARCH=arm64 CGO_ENABLED=0, ~10 МБ)
```

- Activity при старте запускает `libclepsy.so` из `nativeLibraryDir` (`-no-tray -no-open -data <filesDir>/data.json -addr 127.0.0.1:<порт>`), ждёт ответа сервера и открывает WebView. Вся логика (повторы, перенос, планы, Помодоро, холст) — общая с Windows, ничего не переписывается на Java/Kotlin.
- В манифесте `extractNativeLibs="true"` (Gradle: `packaging.jniLibs.useLegacyPackaging = true`), иначе .so не распакуется и запустить его нельзя.
- NDK и gomobile не нужны: проверено, `go build` под android/arm64 без cgo проходит.
- Порт — случайный свободный или фиксированный (например 18080); сервер слушает только 127.0.0.1, `guard` не меняется.
- Кнопка «Назад» → `history.back()` в WebView, на главном экране — свернуть приложение.

## Синхронизация

Модель: у каждого устройства свой `data.json`; при синхронизации телефон отправляет ПК **всё своё состояние**, ПК сливает его со своим и возвращает результат, телефон сохраняет его у себя. Код слияния один (Go) на обеих сторонах.

Что нужно добавить в `store.go`:
- `UpdatedAt` у `Task`, `List`, `Habit`, `Series`, `Sketch` — выставлять при каждом изменении (Create/Update/Toggle/Timer/Reorder/Rollover…).
- Надгробия удалений: `Deleted map[id]time` в `Data` (чистить старше ~60 дней).
- Заметки дня: время правки на дату (`NoteTimes map[date]time`); счётчики Помодоро — слияние по максимуму.
- Правило слияния — «побеждает последняя правка» по сущности целиком (`UpdatedAt`), удаление побеждает правку, сделанную раньше удаления.
- Повторяющиеся задачи: при выполнении копия получает **детерминированный** id (`<id>-<следующая дата>`), чтобы отметка на двух устройствах не дала двух копий.
- Рисунки: метаданные сливаются как остальное, PNG докачиваются отдельными запросами по id.
- Настройки программы (`app`, `pomoSettings`) не синхронизируются — у каждого устройства свои.

Связь:
- На ПК — отдельный слушатель в локальной сети (например `:8092`, только `POST /api/sync` и рисунки), включается в «Настройках» → «Телефон». Там же адрес ПК и код сопряжения; запрос без верного кода — 403. Основной `127.0.0.1:8080` не трогаем.
- При первом включении Windows спросит про брандмауэр — разрешить «Частные сети» должен сам пользователь.
- На телефоне в «Настройках»: адрес ПК + код, кнопка «Синхронизировать», авто-синхронизация при открытии приложения и раз в N минут, если ПК доступен. Работает дома по Wi-Fi; вне дома — тот же механизм через Tailscale (адрес `100.x.x.x`).

## Мобильный интерфейс

Текущая вёрстка рассчитана на окно ПК. Нужна мобильная: нижняя навигация, крупные касания, панель задачи — на весь экран, быстрый ввод снизу. **Сначала показать макет, применять после выбора.**

## Инструменты для сборки APK (на этом ПК их пока нет)

| Что | Откуда | Размер |
|---|---|---|
| JDK 17 (Temurin, zip) | adoptium.net | ~190 МБ |
| Android command-line tools | dl.google.com (`commandlinetools-win-*_latest.zip`) | ~150 МБ |
| platform-tools, platforms;android-35, build-tools;35.0.0 | через `sdkmanager` | ~150 МБ |
| Gradle (wrapper) + Android Gradle Plugin | services.gradle.org, maven.google.com | ~350 МБ при первой сборке |

Всё ставится в одну папку (например `D:\Android\`) без прав администратора и без изменения системных переменных — пути задаются в скрипте сборки и `local.properties`.

Сборка: скрипт `build-android.ps1` — `go build` под android/arm64 → `android/app/src/main/jniLibs/arm64-v8a/libclepsy.so` → `gradlew assembleRelease` → `Clepsy.apk` (подпись своим ключом, ключ вне git). Установка на телефон: скопировать APK и разрешить установку из этого источника, либо `adb install` по USB.

## Порядок работы

1. Поставить инструменты, каркас `android/` (Gradle-проект на Java), `build-android.ps1`; APK с текущим интерфейсом запускается на телефоне.
2. Синхронизация: `UpdatedAt` + надгробия + слияние (с тестами в `main_test.go`), слушатель на ПК, настройки на обеих сторонах.
3. Мобильная вёрстка (после выбора макета).
4. Потом: уведомления о сроках, виджет на главный экран.
